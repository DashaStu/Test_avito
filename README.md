Цель проекта — разработать систему ранжирования объявлений для поисковых запросов пользователей. Задача состоит в том, чтобы для каждого запроса из benchmark_queries отобрать топ-50 наиболее релевантных объявлений из корпуса benchmark_items.


## Решение построено на архитектуре Retrieval + Ranking:
1. Retrieval (Отбор кандидатов)
Для каждого запроса необходимо быстро отобрать ~500 перспективных кандидатов из 189 000 объявлений.
BM25 (по заголовкам и описаниям): для поиска по ключевым словам.
TF-IDF: Дополнительная семантическая фильтрация для учета близости по смыслу.
3. Reranking
Отфильтрованные кандидаты проходят через модель CatBoostClassifier, которая предсказывает вероятность клика (target=1).
Использовала Hard Negative Sampling: в качестве негативных примеров для обучения брались не случайные товары, а "похожие" по поисковым словам, что заставило модель глубже различать товары внутри одной ниши.



## Данные и признаки
В процессе разработки была проведена тщательная работа по отбору признаков (Feature Engineering), исходя из бизнес-логики сервиса объявлений:
* is_same_location: Индикатор совпадения локации пользователя и продавца. Является ключевым фактором для услуг (ремонт, красота).
* price_diff (Относительное отклонение цены): Рассчитывается как (цена - медиана_по_категории) / медиана. Позволяет модели определять "выгодность" предложения независимо от абсолютной цены.
* popularity: Статистика кликабельности item_id из обучающей выборки. Позволяет модели отдавать предпочтение товарам, пользующимся спросом.
* rating и reviews_count: Оценка надежности продавца. Добавлены флаги is_rating_missing и is_reviews_missing, чтобы модель корректно обрабатывала отсутствие отзывов (новые или скрытые объявления).
* bm25_score: Использовался на этапе отбора кандидатов для оценки текстовой релевантности.

Выбранные признаки позволяют модели учитывать не только текстовое сходство (поиск), но и экономическую выгоду (цена), доверие (рейтинг) и удобство (локация).

## В ходе работы были выявлены и решены следующие проблемы:
Проблема бесконечностей (inf): при расчете price_diff возникало деление на ноль. Решение: замена inf на медианные значения и использование np.clip для ограничения диапазона значений.
Ошибка с target в обучающей выборке: из-за некорректного слияния списков позитивных и негативных примеров в df_train попадали только нули. Решение: переписана логика цикла сбора данных, что обеспечило баланс классов и заработавшую корреляцию.
Отсутствие вариативности данных: изначально модель плохо ранжировала из-за малого количества негативных примеров. Решение: увеличено количество негативов (до 10 на 1 позитив) и введены флаги отсутствия отзывов, что повысило точность модели.
